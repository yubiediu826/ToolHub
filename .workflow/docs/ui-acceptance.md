# UI 验收闭环（ui-acceptance）

> 目的：让 AI 在开发过程中持续知道「当前 UI 是否符合用户预期」，而不是做完才发现跑偏。

## 开发前：草案确认（页面级新 UI 必须）

1. AI 产出 UI 草案：ASCII 线框 + 分区说明 + 所用组件清单（`Flu*` / `SerialCube_*`）+ 数据来源。
2. 用户确认草案后才写代码。布局/交互有歧义时先问（用选项式提问，附预览）。

## 开发中：截图自查

每完成一个页面：

1. 运行程序（`.\venv\Scripts\python.exe script-start.py fast` 或 `run.bat`）。
2. 用 ZCode 截图能力（computer-use screenshot）截取实际界面：
   - 明主题 1 张、暗主题 1 张；
   - 窄窗口（触发侧边栏折叠）1 张。
3. 对照 ui-design-spec 与已确认草案逐项自查：语义色、栅格间距、字号层级、控件高度、交互态。
4. 发现偏差当场修复后重截。

## 开发后：交付评审

1. 阶段交付说明附最终截图（明/暗），请用户过目。
2. 用户提出修改 → 修改后更新 ui-design-spec 对应小节，并在 `decisions/` 记录决策（日期 + 原因 + 结论）。
3. 更新后的规范成为下一轮开发的预期基准。

## 验收 checklist（每页面）

- [ ] 草案已获用户确认
- [ ] 明/暗主题截图各 1 张，可读性正常
- [ ] 窄窗口布局不破（折叠侧边栏态）
- [ ] 0 硬编码颜色 / 0 硬编码字号 / 0 Qt 内置控件
- [ ] 用户可见文案均已 qsTr
- [ ] 高频刷新无卡顿（日志/仪表盘滚动流畅）
